## Резюме: что требуется по кейсу

**Суть задачи:** разработать AI-агента (ассистента) для создания и редактирования рекламных кампаний, который помогает менеджеру заполнять обязательные поля, предлагает недостающие данные на основе контекста и доводит кампанию до отправки в Content Broker.

### Основные требования

1. **Работа с доменной моделью**
   - Использовать предоставленную упрощённую модель данных (ссылка по QR-коду).
   - Обязательные поля должны быть заполнены — без них кампанию сохранить нельзя.
   - Необязательные поля могут оставаться пустыми.
   - Агент не принимает решения за пользователя, но **предлагает** варианты для обязательных полей, если менеджер их пропустил (название, места показа, креативы и т.д.).

2. **Жизненный цикл кампании**
   - Создание: агент собирает данные из первичного промпта, предлагает недостающее, помогает сформировать креативы (баннеры, динамический контент).
   - Редактирование: по запросу менеджера (например, по ID кампании) агент предлагает правку и сохраняет поверх существующей сущности.
   - Сохранение: **все сущности** (итоги работы ассистента) должны сохраняться в базе данных — с историчностью и аудитом.
   - Отправка: после подтверждения пользователем кампания отправляется в Content Broker (там заглушка ответа — «принято»). Ваша валидация бэкэнда должна пропускать только корректные сущности.

3. **Интерфейс**
   - Чат-интерфейс для взаимодействия с агентом.
   - Можно использовать готовые библиотеки (Ant Design, Material и т.п.).
   - **UX важнее визуала:** меньше нажатий, меньше раздражающих блокирующих элементов, никакой лишней рекламы.
   - Визуал тоже будет оцениваться (спикер — фронтендер).

4. **Валидация и противоречия**
   - Проверять обязательные поля и отсутствие противоречий.
   - Для взаимоисключающих сегментов (например, 18–35 и 65+) рекомендуется **выдавать предупреждение**, а не жёсткий запрет — чтобы не отсекать валидные кейсы.

5. **Демо-кейс**
   - В задании есть пример, но **лучше придумать свой** (например, кампания для женщин старше 35 — аквапарк, баня и т.д.).
   - Можно использовать сегменты по возрасту, полу, месту жительства, интересам.

6. **Экономическое обоснование (для презентации)**
   - Цель — повысить производительность менеджеров, снизить рутину и ошибки.
   - Конкретных цифр нет; для презентации можно сказать, что одна кампания сейчас занимает **около часа** (это «враньё, но для презентации сойдёт»).
   - Количество менеджеров сокращать не планируется — только облегчить их работу.

7. **Технические ограничения**
   - Content Broker — внешняя высоконагруженная система, доступа к ней нет; в задании есть заглушка ответа.
   - За пределами контракта с брокером вы не ограничены — как хранить данные внутри, решаете сами.
   - Модель данных упрощена, но похожа на реальную (в реальности ~50 таблиц).

8. **Главная цель**
   - Показать полноценный алгоритм работы рекомендательной модели: чтобы на запросы вида «сделай мне нормально» агент предлагал корректные варианты и корректно заполнял кампанию.

**Критерии оценки:** работающий алгоритм, корректные рекомендации, удобный UX, аккуратный визуал, собственная демонстрация кейса.
